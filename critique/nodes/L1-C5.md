# L1-C5 critique (§12–§16)

1. **Anchor:** §13 · **Class:** missing-failure-mode
   **Defect:** `board()` assumes columns `est_tokens`, `question_id`, and `ts` exist whenever any telemetry row exists. After §14 step 2 (orchestrator logs `spawn`) but before any researcher `read` event, `rows` is non-empty but likely lacks `est_tokens`/`question_id`, so `df[df.event == "read"].est_tokens` or the `meta` agg raises KeyError/AttributeError and the whole dashboard dies — the `if not rows` guard only covers the zero-rows case.
   **Consequence:** Dashboard crashes exactly during early-run monitoring, when the user is told to watch it; telemetry looks broken though logging is fine.
   **Severity:** medium
   **Fix sketch:** Guard with `df = df.reindex(columns=[...], fill_value=None)` or check column presence before each groupby, as already done for dead-end cols.
   `check-globally:` verify against §6 whether `spawn`/`done` events actually omit `est_tokens`/`question_id`.

2. **Anchor:** §14 step 4 · **Class:** undefined-term
   **Defect:** "spawn a synthesizer for each qid whose evidence has fully landed" never defines "fully landed," and it cannot be per-qid-simple for Q4, whose evidence arrives in batches split across Waves 2 and 3 (steps 5–6). Nothing says whether Q4 gets one synthesizer after Wave 3 or incremental synthesis per batch.
   **Consequence:** Orchestrator may synthesize Q4 on partial evidence and mark the section done, or stall waiting for a completeness signal that no artifact provides.
   **Severity:** medium
   **Fix sketch:** Define landed = all spawned researchers for that qid have logged `done` and, for Q4, all census batches dispatched; synthesize Q4 only after the last batch.

3. **Anchor:** §15 · **Class:** contradiction
   **Defect:** The fallback ladder is stated as "live raw fetch → Wayback → `unknown` + dead_end," terminating at unknown; the next sentence adds "WebFetch-digest snapshots are a last resort." The ladder position of the WebFetch-digest step relative to `unknown` is unspecified — and internally inconsistent, since a "last resort" after the terminal rung is unreachable.
   **Consequence:** Some researchers will record `unknown` without trying WebFetch while others insert the digest step, producing inconsistent evidence quality and dead-end counts across agents.
   **Severity:** medium
   **Fix sketch:** State the ladder as live → Wayback → WebFetch-digest (model-mediated, low confidence) → unknown + dead_end.
   `check-globally:` §7/§9 may already fix this ordering.

4. **Anchor:** §14 step 4 vs §15 · **Class:** ambiguity
   **Defect:** Step 4 tells the orchestrator to filter for "venue-level `bot-blocked` dead ends" (a specific reason string), while §15 says "first hard 403 on a venue gets logged as a venue-level dead end" without mandating that string; neither section binds researchers to a controlled `reason` vocabulary.
   **Consequence:** Researchers logging reason "403" or "paywall" are invisible to the orchestrator's fail-fast filter, so blocked venues keep getting live-fetched by later batches, burning token budget.
   **Severity:** medium
   **Fix sketch:** Enumerate allowed `reason` values (e.g. `bot-blocked`, `paywall`, `not-found`, `no-coverage`) once and reference it from §6, §14, §15.
   `check-globally:` §6/§11 may define a reason enum.

5. **Anchor:** §14 step 5 · **Class:** missing-failure-mode
   **Defect:** Wave 2 is gated on `matrix/census.csv` existing; the partial-census case is handled, but there is no branch for Q1 failing outright (all census venues bot-blocked, agent splits and children also fail). No timeout, retry limit, or degraded-mode instruction exists.
   **Consequence:** Q4 (and its Wave-3 remainder) can stall indefinitely or silently drop out of the run with no NOT-RESEARCHABLE-style section explaining why.
   **Severity:** medium
   **Fix sketch:** Add: if Q1 ends UNRESOLVED, mark Q4 blocked-on-input in its section and proceed; never spin extra Q1 retries beyond one split generation.

6. **Anchor:** §14 step 4 · **Class:** ambiguity
   **Defect:** "confirm no agent's self-reported reads >32k" is ambiguous between (a) summed `read`-event est_tokens (what §13 computes) and (b) the agent's `done` `cum_tokens` self-attestation — the two are expected to diverge (§13 warns at >2k divergence, §12 method note calls self-reports attestations). Which number triggers enforcement, and what the enforcement action is mid-run, is unstated here.
   **Consequence:** Two orchestrator runs make different cap calls on the same telemetry; an over-cap agent may face no defined consequence.
   **Severity:** medium
   **Fix sketch:** Enforce on summed `read` events; on breach, note it in the agent's section and prefer splits next wave.
   `check-globally:` §5 (post-hoc enforcement, split protocol) may already specify the action.

7. **Anchor:** §16 vs §14 · **Class:** broken-cross-ref
   **Defect:** The Phase 0 kickoff says "Execute §8 Phase 0 only," but phases are defined in §14 (the runbook); §8 is the scaffold tree per the map. A fresh session following the pointer to §8 finds no phase definition, only the artifact list — it will likely still succeed, but the verification/restart steps live in §14 step 1.
   **Consequence:** A literal-minded Phase-0 session may build the scaffold but skip `bash -n`/`py_compile` verification and the restart instruction, which are stated only in §14.
   **Severity:** low
   **Fix sketch:** Reword to "Execute §14 step 1 (Phase 0), building the §8 scaffold exactly."

8. **Anchor:** §14 step 2 · **Class:** infeasible-as-written
   **Defect:** "confirm `researcher` and `synthesizer` are registered (halt + tell user if not)" gives no mechanism: file existence under `.claude/agents/` is checkable, but session registration is not directly introspectable by the orchestrator, and the spec doesn't say which proxy check to use.
   **Consequence:** Orchestrator either skips the check or false-passes on file existence while the session never registered the agents, then fails at first spawn.
   **Severity:** low
   **Fix sketch:** Define the check as "attempt a trivial spawn of each agent type; halt on spawn error," or accept file-existence as the proxy explicitly.

9. `check-globally:` §12 header field "model configured: <from orchestrator spawn logs>" presumes the §6 `spawn` event carries a model field — verify §6 includes one, else the template is unfillable.
10. `check-globally:` §12 method note's "frozen corpus" is undefined in this chunk — verify §10 defines the corpus and a freeze point (evidence files immutable once synthesis starts).
