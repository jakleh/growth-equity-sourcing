# L1-C3 critique — §4 Architecture, §5 Caps/split, §6 Telemetry, §7 Snapshots/citations/matrix

1. **Local-file reads count against budget but are never required to be logged.**
   - Anchor: §5 (accounting bullet), §6 (researcher logging rule)
   - Class: contradiction
   - Defect: §5 says the cap covers "fetched digests + files read into context" and that "any part of a snapshot later Read into context does" count. But the only mandatory logging trigger in §6 is "after EVERY WebFetch/WebSearch." Reads of snapshot `.txt`, evidence JSON, or briefs via the Read tool are budget-relevant per §5 yet have no logging obligation, and the `read` event schema is URL-keyed.
   - Consequence: Dashboard (§13, sums `read` events) and post-hoc audit systematically undercount cumulative tokens — the tracked ceiling silently lies exactly when researchers do the §7 quote re-derivation work.
   - Severity: high
   - Fix sketch: Extend the logging rule to "after every WebFetch/WebSearch *and every Read of a file body*," and allow `url` to be a file path.

2. **No overrun remedy exists for synthesizers, and split-heavy questions guarantee they hit it.**
   - Anchor: §5 (split protocol steps 1, 3), §6 (synthesizer channel), §4
   - Class: missing-failure-mode
   - Defect: The split protocol's trigger is defined only for researchers ("Researcher nearing budget... returns status: partial"). Step 3 forces the *single* base-qid synthesizer to read *all* `evidence/q4*.json` (plus snapshots for entailment checks per §10) — the more the researcher side splits, the larger the one synthesizer's mandatory read set, with no split, partial-status, or shedding rule defined for it.
   - Consequence: On Q4-scale questions the synthesizer either blows the 32k cap (post-hoc audit flags it after the damage) or truncates its reading silently, producing under-verified sections.
   - Severity: high
   - Fix sketch: Define per-batch synthesizers (one per child qid, plus a merge step) or an explicit synthesizer partial/split path via its `done`-equivalent in `synth-<qid>.jsonl`.

3. **`grep -qiF` quote verification is line-based; any quote spanning a line break in the `.txt` fails.**
   - Anchor: §7 (quote verification)
   - Class: infeasible-as-written / goodhart-risk
   - Defect: §7 says the `.txt` is "whitespace-normalized" but never says newlines are collapsed to a single line; if the extraction keeps line breaks, fixed-string grep cannot match any multi-line quote regardless of fidelity. Agents instructed that grep "must succeed" will predictably shorten quotes to sub-line fragments to pass the check.
   - Consequence: Either valid quotes get `quote_verified: false` (false downgrades), or the metric is gamed with trivially short fragments — the verification field stops meaning what §11 consumers think it means.
   - Severity: medium
   - Fix sketch: Specify that snap.sh normalizes the `.txt` to one whitespace-collapsed line (or mandate `tr -s '[:space:]' ' '` on both quote and file before grep), and set a minimum quote length.

4. **`predates_investment = n` is unreachable, and a same-day capture falls between the rules.**
   - Anchor: §7 (predates check, matrix columns)
   - Class: ambiguity
   - Defect: The decision rule maps non-empty + strictly-earlier → `yes` and empty → `unknown`; no rule ever produces `n`, though the CSV schema declares `(y/n/unknown)`. Also, `to={YYYYMMDD}` is inclusive, so a capture dated exactly the investment day returns non-empty but is not "strictly earlier" — that case is assigned to neither branch.
   - Consequence: Agents will fill `n` by improvised criteria (or never), making the matrix's headline column inconsistent across researchers; same-day captures get random treatment.
   - Severity: medium
   - Fix sketch: Rule that non-empty-but-not-strictly-earlier → `unknown` (or define what evidence licenses `n`, e.g., confirmed page-creation date after investment).

5. **`read` events from WebSearch have no representable source.**
   - Anchor: §6 (event schema), §5 (accounting)
   - Class: ambiguity
   - Defect: WebSearch results count as fetched content per §5 and must be logged as `read`, but the schema's example keys the event on `url`; only `dead_end` gets `url_or_query`.
   - Consequence: Researchers improvise (empty url, fake url, query string in url), degrading audit joins between telemetry and snapshots.
   - Severity: low
   - Fix sketch: Allow `"query":` as an alternative to `"url":` on `read` events.
