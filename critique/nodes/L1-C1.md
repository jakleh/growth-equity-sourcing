# L1-C1 critique — doc header; §0; §1; §2

1. **Unsatisfiable DoD checkboxes with no remediation path**
   - Anchor: §1 (DoD bullets 7–8), §0.1
   - Class: missing-failure-mode
   - Defect: DoD is prefixed "do not stop before all boxes check," but bullets 7–8 assert historical facts ("no agent... exceeded 32,000 tokens," "each researcher's reported #dead_ends matches its telemetry events") that are verified post-hoc (per §5, enforcement is post-hoc). If a Wave-1 agent overshoots the cap or one dead end goes unlogged, the box can never become true — the spec defines no remediation (discard that agent's evidence? re-run the question? annotate and proceed?).
   - Consequence: Orchestrator either loops forever trying to satisfy an unfixable checkbox or silently reinterprets the DoD; either way the run's completion signal is broken.
   - Severity: high
   - Fix sketch: Rewrite bullets 7–8 as "any breach is documented in findings.md with the affected question downgraded per <procedure>," and define that procedure.

2. **"Enforced" cap vs attestation-grade self-report**
   - Anchor: §2 principle 6, §1 bullet 7, §0.1
   - Class: goodhart-risk (with an internal contradiction)
   - Defect: §2 P6 says "The 32k cap is enforced," but §1 bullet 7 concedes the only measurement is the agent's own `est_tokens` self-logging ("attestation-grade"). Nothing prevents an agent from under-logging (or simply forgetting `log.sh` calls) to pass; the metric being both self-reported and a hard DoD gate is the classic setup for silent gaming.
   - Consequence: Dashboard and DoD show compliance while actual context loads exceed 32k — the exact reasoning-degradation the cap exists to prevent, now invisible.
   - Severity: medium
   - Fix sketch: Downgrade P6's wording to match §1, and add one independent check (e.g., orchestrator sums bytes of snapshot files an agent read, or compares fetch count × median page size against reported totals).

3. **"Spot-checked by the orchestrator" is an undefined procedure, and the map suggests the orchestrator can't do it**
   - Anchor: §1 bullet 8
   - Class: undefined-term (map-vs-chunk tension)
   - Defect: The zero-dead-end spot-check names no method, no sample size, and no fail criterion. Per the map, §4 restricts the orchestrator to `sections/*.md`, telemetry aggregates, and `census.csv` — none of which contain the fetch-by-fetch trail needed to detect an unlogged dead end — and the researcher has exited by audit time, so it cannot be interrogated.
   - Consequence: Orchestrator either fabricates a token "check noted in findings.md" (satisfying the letter of the box while verifying nothing) or violates its §4 read restrictions.
   - Severity: medium
   - Fix sketch: Define the check concretely (e.g., "orchestrator greps the agent's raw telemetry JSONL for fetch events lacking a subsequent claim or dead-end entry") and explicitly exempt this from the §4 read restriction.

4. **"Populated" matrix has no acceptance criterion in the DoD**
   - Anchor: §1 bullet 6, §2 (survivorship-bias para)
   - Class: ambiguity
   - Defect: `matrix/portfolio_venue_matrix.csv` "is populated" — the chunk never says which portfolio, which venues, or how many rows/columns constitute populated; within this chunk the artifact is otherwise referenced only obliquely as "the Q4 matrix." A file with headers plus one `unknown` row satisfies the text.
   - Consequence: The checkbox passes on a near-empty file; Q4's load-bearing output silently under-delivers.
   - Severity: medium
   - Fix sketch: Bind the bullet to the §7 schema and §3 Q4 brief ("one row per portfolio company enumerated under Q4, all schema columns filled or `unknown`+reason"). check-globally: verify §3 Q4 and §7's CSV schema actually pin down row scope.

5. **"streamlit run ... works" is untestable as written**
   - Anchor: §1 bullet 9
   - Class: ambiguity / goodhart-risk
   - Defect: "Works" could mean launches without traceback, or renders per-agent token curves from real telemetry. An app that starts but plots nothing (e.g., wrong JSONL path) checks the box.
   - Consequence: Dashboard-based cap auditing (bullet 7's only visualization) silently shows nothing while DoD reads green.
   - Severity: low
   - Fix sketch: "Launches without error AND displays nonzero cumulative read tokens for every spawned researcher."

6. **Two referents for "telemetry" collide**
   - Anchor: §2 (Instrumentation), §1 bullet 7
   - Class: ambiguity
   - Defect: §2 uses "telemetry" for the GE project's locked schema question (the [OPEN] behind Q9: flat vs split), while §1/§6 use "telemetry" for this run's own JSONL instrumentation. A researcher assigned Q9 receives briefs saying telemetry design is open while operating under a spec that mandates a specific telemetry design.
   - Consequence: Q9 researcher or synthesizer conflates the two and "resolves" Q9 by citing this run's §6 design — speculation dressed as resolution, violating §2 principle 5.
   - Severity: low
   - Fix sketch: Rename the run's instrumentation ("run-telemetry") or add one disambiguating sentence in §2's Instrumentation bullet.

7. check-globally: §0.2 says the orchestrator "logs the configured model at spawn" — verify §6's event schema actually has a field/event for this, else the §12 `model_self_reported` labeling has no configured-model counterpart to compare against.
8. check-globally: §2 asserts "one synthesizer per question" in passing — verify §4's role definitions and §14's wave plan use the same cardinality (13 synthesizer runs, not per-wave synthesis).
9. check-globally: §2 funnel jargon "multiple T's" is defined nowhere in this chunk; if no later section defines it, it is an undefined-term in the only context researchers inherit.
