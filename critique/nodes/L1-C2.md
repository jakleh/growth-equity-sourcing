# L1-C2 critique — §3 Question backlog (backlog.yaml, Q1–Q13)

1. **Anchor:** §3 Q1 (note) + Q4 (depends_on, note)
   **Class:** missing-failure-mode
   **Defect:** Q1 says "Deliver even a partial census early" and Q4 batches are cut from `matrix/census.csv`, but there is no reconciliation protocol for companies added to the census *after* batches are cut. Nothing says the orchestrator re-diffs census.csv or issues catch-up batches.
   **Consequence:** Companies discovered late silently never get Q4 rows; `portfolio_venue_matrix.csv` looks complete but is missing an unknown fraction of the portfolio.
   **Severity:** high (silently lies)
   **Fix sketch:** Require Q1 to version the census (or mark rows `added_wave_N`) and require the orchestrator to diff census.csv against batched companies before each wave.
   `check-globally:` §14 Wave-2 gate may partially cover this, but the chunk itself states no re-diff rule.

2. **Anchor:** §3 Q4 (predates check)
   **Class:** ambiguity
   **Defect:** predates=yes requires a capture timestamp "STRICTLY EARLIER than the investment date," but the CDX query uses `to={YYYYMMDD}` which is inclusive of that day, and capture timestamps are 14-digit while the investment date is 8-digit. A capture *on* the investment day is returned but is neither strictly earlier nor an empty result — its predates value is undefined, as is the comparison convention (compare first 8 digits? full timestamp vs date+000000?).
   **Consequence:** Different researcher batches encode same-day captures inconsistently (yes vs unknown), corrupting the matrix column that backtesting reads.
   **Severity:** medium
   **Fix sketch:** Use `to={investment date minus 1 day}` so any non-empty result is strictly earlier by construction, and state the truncate-to-8-digits comparison rule.

3. **Anchor:** §3 Q3
   **Class:** goodhart-risk
   **Defect:** Q3 must output a "match fraction" and says "a negative answer is itself a P0 finding," but never defines the threshold that makes the answer negative, nor whether `ambiguous` classifications count in the denominator (or as non-matches). With ≥15 samples and a three-way label, the same data supports fractions from e.g. 40% to 65% depending on denominator choice.
   **Consequence:** The go/no-go verdict on enumeration channel #3 — feeding the locked next step — is decided by an unstated researcher-side convention rather than by the spec.
   **Severity:** medium
   **Fix sketch:** Define fraction = yes/(yes+no+ambiguous), report ambiguous count separately, and set an explicit usability threshold (or explicitly delegate the threshold to §12 synthesis).

4. **Anchor:** §3 Q4
   **Class:** undefined-term
   **Defect:** Q4 tells researchers to "respect venue-level fail-fast flags in your brief," but no flag vocabulary, trigger condition, or format is defined in the backlog, and the mapping/context in this chunk never introduces the concept.
   **Consequence:** Orchestrator and researchers improvise flag semantics per batch; a venue hard-blocked in batch 1 keeps burning fetch budget in batches 2–8.
   **Severity:** medium
   **Fix sketch:** Define the flag set (e.g. `venue: skip|wayback-only|live-ok`) and where it lives (batch brief header), plus who updates it between waves.
   `check-globally:` §15 defines a fallback ladder but the map does not mention fail-fast flags anywhere.

5. **Anchor:** §3 Q11–Q13 (class B)
   **Class:** unstated-assumption
   **Defect:** Q11–Q13 are `NOT-RESEARCHABLE` yet each says "findings.md must state..." / "the findings section states...". The chunk assigns no producer: class-B questions presumably get no researcher, and it is unstated whether a synthesizer runs without evidence files or the orchestrator writes these sections directly.
   **Consequence:** Three of thirteen sections have no owner; either they are skipped (DoD failure at the end) or a synthesizer is invoked against a nonexistent `evidence/<qid>.json` and errors mid-run.
   **Severity:** medium
   `check-globally:` §10/§12/§14 may assign class-B section authorship; map is silent on it.

6. **Anchor:** §3 backlog.yaml header comment + Q8/Q9 + Q11
   **Class:** contradiction
   **Defect:** The header comment declares exactly two classes ("A = web-researchable | B = requires firm input or design decision") and "priority: P0 highest," but the file then uses out-of-schema values: class `A-input` (Q8, Q9) and priority `P0-flag` (Q11). `A-input` is only defined via an inline comment on Q8; `P0-flag` is never defined at all.
   **Consequence:** Any wave-scheduling or dashboard logic keyed on class/priority (e.g. "run all P0 first") mishandles Q11 — is it Wave-1 work or a standing flag? — and treats Q8/Q9 inconsistently.
   **Severity:** low
   **Fix sketch:** Extend the header comment to enumerate all three classes and define `P0-flag` (e.g. "P0 visibility, no research work").
