**Process.** Three inputs, produced independently and then adjudicated:

1. **Orchestrator review** (this session): independent findings written down *before* reading the agent review, plus direct fidelity checks against the handoff doc once provided.
2. **Adversarial review agent** (`claude-fable-5`): 26 severity-ranked findings. It verified dashboard failure modes by executing the code against pandas, checked external claims against official docs/pages where the proxy allowed, and explicitly labeled which findings were judgment calls.
3. **Documentation fact-checker** (claude-code-guide agent): doc-cited answers on subagent discovery, frontmatter `model:` semantics, WebFetch/WebSearch behavior, model observability, permissions, and nesting.

Per the request, the agent's review was treated with skepticism: every finding was cross-checked against my own list, the docs agent's citations, or the handoff text before adoption. The diff between the baseline commit ("as provided") and the revision commit is the full set of changes.

## Documentation facts the revision rests on

- `.claude/agents/` is discovered by walking **up** from the session cwd; file-edited agents require a session restart (mid-session file writes don't register). → agents moved to repo root; two-phase restart kept; preflight diagnoses cwd-vs-restart.
- WebFetch returns a **small-model digest** of the page (truncated for long pages), not the page. → dual-artifact snapshots (extract + raw curl capture), grounding grades, method-note disclosure.
- WebSearch returns **titles + URLs only** (no snippets). → noted in §0.3; budget math unaffected.
- Frontmatter `model:` accepts aliases/full IDs/`inherit`; invalid or org-excluded models fall back to the inherited model. **No documented way** for a subagent to introspect its model or the parent to observe it. → `model_used` telemetry renamed `model_configured`; §0.2 rewritten; "run the session on the target model" mitigation added.
- Subagents **can** nest (depth ≤5) in current Claude Code — the baseline spec's §0.4 ("subagents cannot spawn subagents") was factually stale. → reframed as a design rule, enforced by omitting `Agent`/`Task` from both agent files.
- Unattended parallel runs stall on permission prompts unless `permissions.allow` rules exist. → `.claude/settings.json` scaffolded (§8), preflight check added (§14.2).

## Round 2 — external Gemini review adjudication (2026-07-02)

The user supplied an adversarial Gemini review of the revised spec, to be treated with the same skepticism protocol. Five claim areas; verdicts below. Net effect: one genuine bug found and fixed (plus a sibling bug it missed), several proportionate hardenings adopted, two claims rejected as factually wrong.

**G1. "Bot protection slaughters curl; CDX gets rate-limited; Q4 delivers zero signal." — Partially accepted; the pressure test exposed a real bug.**
The blocking risk itself was already handled (live → archive → unknown fallbacks, extract_only capture kind, §14.3 staggering — Gemini did not engage with those). But probing its CDX scenario against the actual script found a genuine false-negative bug: `curl -sS` without status checking exits 0 on HTTP 429/503, so a rate-limit response body (or empty body) could be echoed as if it were capture data — or worse, fall through to `NONE`, conflating *lookup failure* with *definitive absence*. In a run whose first principle bans manufactured false negatives, that was the single most valuable finding of this round. Fixed: `cdx.sh` now checks the HTTP status, retries with backoff, and emits a three-way vocabulary (`capture` / `NONE` / `CDX-ERROR`); the Q4 brief, researcher rules, §15, and the dead-end taxonomy all distinguish `cdx-error` from `no wayback coverage`. The same audit found a sibling bug Gemini missed: `snap.sh` lacked `-f`, so a 403 challenge page would have been *saved as a raw capture* and inflated the raw-grounding metric — also fixed. Rejected as stated: "Q4 will deliver exactly zero signal" (Inc./Fast 500/trade-show/press/Wayback routes remain fetchable; WebFetch is Anthropic-infrastructure fetching, not local curl; the venue matrix degrades per-venue, not wholesale). Added instead of accepted rhetoric: the first Q4 batch is an explicit venue-viability probe feeding later batch briefs alongside Q5's access findings.

**G2. "Token accounting is a mirage / fatal misunderstanding." — Rejected as diagnosis; accepted as a documentation fix.**
The critique attacks a claim the spec doesn't make. The 32k ceiling bounds *ingested content* as a signal-to-noise discipline (the upstream principle is explicit: "context degradation is signal-to-noise, not token count"); it was never a context-window gauge, and subagent windows are far larger than the ceiling, so the "silently at 45k+" arithmetic identifies overhead the metric deliberately ignores rather than a failure mode. Its "hallucinate citations before telemetry triggers" chain also misses that citation integrity is enforced by the snapshot/entailment layer, not the budget. Accepted: §5 now states all of this explicitly ("what the ceiling is — and is not"), so no future reader repeats Gemini's misreading.

**G3. "sleep is not a semaphore; slug collisions between parallel agents." — Half accepted, half rejected.**
Accepted: per-agent sleeps genuinely don't pace a fleet. Added `scripts/pace.sh` — a cross-agent per-host spacing lock (python `fcntl`, portable to macOS where `flock(1)` doesn't exist) — called by `snap.sh`/`cdx.sh`; archive.org is the shared hot path and now has fleet-wide 3s spacing plus cdx backoff. WebFetch pacing remains advisory + orchestrator staggering (it can't be locked from scripts). Rejected: the slug-collision scenario is factually wrong on the spec's own text — every agent writes under `snapshots/<its-own-qid>/`, and split children have distinct qids (`q4a1` ≠ `q4a2`), so two agents never share a snapshot directory. A one-line rule against *self*-collisions (unique slugs within one's own qid) was added because it costs nothing.

**G4. "Compaction amnesia; LLMs are bad at mechanical concatenation." — Accepted as sharpenings of existing mechanisms.**
Compaction is precisely why `run-state.md` already existed; the fair gap was mid-wave timing, so run-state is now written *before* each spawn round (intent journal) and the recovery procedure reconciles telemetry `spawn`-without-`done` against evidence files. The concatenation point attacks a strawman — "mechanical" always meant a shell op, not the model restating CSV — but the ambiguity was real enough to close: `scripts/merge_matrix.sh` now does the assembly deterministically with row-count reporting, and the runbook forbids assembling CSV content in-context.

**G5. "Billing catastrophe via silent model fallback." — Rejected in substance; one cheap mitigation adopted.**
The scenario is direction-confused: fallback is to the *inherited session model*, and §0.2 already directs running the session on the target model, making a fallback cost-neutral by construction; Fable 5 sits above Opus in the lineup, so "silently paying Opus prices" would be a *downgrade* scenario, not a blowout; the "standard nomenclature" it cites (`claude-3-5-haiku-20241022`) is stale; and the fleet is capped at 4 concurrent with split depth 1, not "50 parallel agents doing recursive scraping" (total run scale was already surfaced as §0.6). Adopted kernel: model availability is user-verifiable even though it isn't run-verifiable — Phase 0 now has the user confirm `claude-fable-5` in the model picker, and Phase 1 gains a no-web canary spawn proving spawn → permissions → telemetry → reply mechanics before the fleet launches.
